How JarrVis works

JarrVis shows which taxa contribute to which functions in a microbiome, and how that differs between groups of samples. This page explains how the web version is built, how every number on screen is calculated, and where it is going next.

What it does

A stratified function table records, for every sample, how much each taxon contributes to each function: for example how many RPKM of EC:2.1.1.45 in sample 31D come from Streptococcus. JarrVis turns that table, plus a sample metadata file, into four linked views that answer three questions:

  • Which functions are most abundant, or differ most, between groups of samples?
  • Which taxa are responsible for a given function, and does that change between groups?
  • How does contribution flow from groups, through taxa, to functions?

It is a rebuild of JarrVis (preprint). The original's groups → taxa → functions Sankey is kept. The rebuild needs no R install or server, reads PICRUSt2 and HUMAnN output directly, and copes with tables of hundreds of thousands of rows.

Design principles

Your data stays on your computer

The app is a static website. Files are read inside the browser and never uploaded; there is no server or account.

One data engine

DuckDB-WASM, a full SQL database compiled to run in the browser, holds the table once. All filtering, grouping and ranking is SQL.

Charts get summaries, not raw rows

Inputs can be hundreds of MB. Charts only ever receive a capped summary: the top functions and top taxa, with the rest folded into Other.

Linked views over one shared state

Settings and selections live in one small object. Each view is a query plus a chart on it, so selecting a function anywhere updates every view.

How data flows

  1. Load. Each file is read by DuckDB into a table with every column as text, so sample IDs such as 007 keep their leading zeros. A file goes into a staging table first and only replaces the previous one if it loads, so a bad file never wipes good data. TSV, CSV and TXT are accepted, optionally gzipped.
  2. Detect and convert. The stratified table's format is recognized from its column names (or chosen by hand) and rewritten into four columns: sample, taxon, function, contribution.
  3. Validate. Checks produce messages at three levels. Only errors block the data. The original upload is kept, so choosing a different format re-reads it without reloading.
  4. Clean tables. Valid data becomes typed tables. Each taxon string is split into ranks, using the optional taxonomy file when the taxa are IDs.
  5. Summarize and draw. Each view asks DuckDB for exactly the summary it needs, given the current settings, and redraws when they change.

2. Sample metadata

Sample IDs in the first column, whatever it is called, then at least one column to group samples by. Every non-empty column is offered as a grouping.

3. Taxonomy (optional)

Needed only when the table's taxa are IDs, as PICRUSt2's are. The first column holds the IDs. The lineage can be one column (a QIIME 2 taxonomy.tsv works as is) or one column per rank, as DADA2 writes. Lineages without rank prefixes are read by position, kingdom first. Table taxa missing from the file are reported.

How the numbers are calculated

Group values: mean or total

Every view except the per-sample stacked bar works on group values. For group g and any set of taxa and functions:

total(g) = sum of contributions over all samples in g mean(g) = total(g) ÷ n(g) n(g) = samples in g that have any row in the table

A sample with no row for a particular taxon and function counts as zero, so a rare function is not inflated by averaging only over the samples where it was seen. Samples with no value in the grouping column, or with no data at all, are left out and reported.

Collapsing taxonomy

  • Ranks are found by their prefixes (k__ or d__, p__, c__, o__, f__, g__, s__), not by position, with ;, | or HUMAnN's g__X.s__Y as separators.
  • Values such as NA, unclassified or empty mean the rank is unassigned.
  • Taxa are grouped by their whole lineage down to the chosen rank, so two genera with the same name under different families stay separate.
  • A taxon with no name at the chosen rank is labelled after its nearest named parent, such as Unclassified Neisseriaceae.

Ranking functions

The heatmap and the Sankey both pick their top functions with the same ranking, chosen in the toolbar:

  • Highest overall: the sum of the function's group values. With mean values, each group weighs the same however many samples it has.
  • Largest difference between groups: the highest group value minus the lowest, with a group lacking the function counted as zero.

The heatmap also draws this difference as a column beside it. With two groups it is signed (second group minus first), so the bar's direction shows which group is higher. With more groups it is highest minus lowest.

An absolute difference tends to favour abundant functions. These are descriptive comparisons of group means, not statistical tests.

Top N and Other

Charts show a fixed number of items and fold the rest into a grey Other, so a large table never produces an unreadable chart. Taxa are ranked by their value in the data on screen: by total flow in the Sankey, and by group values in the stacked bar, so the taxa and their colours stay put when switching between per-group and per-sample bars.

Sankey flows

A group → taxon link carries that taxon's group value summed over the functions shown. A taxon → function link carries its value summed over the groups. Flow in and out of every taxon therefore balances. Highlighting a group or function splits each link into its own share and a faded remainder, so the layout never shifts and the highlighted part is drawn to scale.

The four views

A sticky toolbar holds the settings every view shares: group-by column, taxonomic level, mean or total, function ranking and function search. The views run down the page in the order you are likely to drill down. Selecting something only changes views below it, so the page doesn't jump.

A Try the example data button loads the TSD metagenomes from the original JarrVis: 229,340 rows, 10 samples in two groups, Kraken2 taxonomy and 995 EC numbers.

Colour and accessibility

  • Amounts use one blue ramp, light to dark (reversed in dark mode, so small values always fade into the background).
  • Taxa use 8 fixed colours, checked to stay distinct for the common forms of colour blindness. They are handed out in a fixed order and never reused; a 9th taxon is grey and keeps its label, or joins Other.
  • Differences use a blue ↔ red pair around zero.
  • Names are always written out, in labels, legends or tooltips, so no information depends on colour alone. Text uses text colours, never a series colour.
  • Charts follow the system's light or dark mode and redraw when it changes.

Export

Each chart downloads as SVG (vector, for editing in Illustrator or Inkscape), PNG (3× resolution) and TSV (the full summary behind it, not just what is drawn). Images are always drawn in light colours on white, whatever the screen mode, and include the stacked bar's legend. The table downloads as TSV with one column per rank. Files are created in the browser; nothing is sent anywhere.

Testing and deployment

  • The data layer has automated tests (94 at present) that run the same DuckDB engine and SQL as the browser, on small hand-made tables and on the committed example files.
  • Every push to the main branch type-checks, tests and builds the app, then publishes it to GitHub Pages. A failing check stops the release.
  • Each change is also checked by hand in the browser before it is committed.

Limits and what's next

Current limits

  • Group comparisons are descriptive. There are no significance tests or standardized effect sizes yet.
  • Data is never saved: reloading the page means loading the files again.
  • The tool is designed for a desktop screen; on a phone the toolbar takes too much room.

Planned

  • Saved views and shareable links. Settings, not data, stored in the link or in the browser; whoever opens a link loads the same files and sees the same view. Links to the example data open it directly.
  • Effect sizes. Rank functions by Cohen's d or log2 fold change, alongside the absolute difference.
  • More filters. Taxon search, a contribution or prevalence threshold, choosing and reordering groups (e.g. months in a time series).
  • Comparison mode. Two groups side by side.
  • More inputs and output. Microbiome Helper output, and PDF export.
